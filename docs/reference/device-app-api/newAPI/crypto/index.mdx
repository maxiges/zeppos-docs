The `@zos/crypto` module provides a comprehensive suite of cryptographic primitives optimized for Zepp OS applications. It enables developers to secure sensitive user data, verify data integrity, authenticate messages, and handle digital signatures directly on the device using low-overhead implementations, utilizing hardware acceleration where available.

## Import

To use the cryptographic features, import the necessary factory functions, algorithm constants, and helper parameters from the module:

```js
import { alg, createCrypto, ecp_dp, encryptKey } from '@zos/crypto'
```

## Architectural Breakdown & Category Guides

### 🛡️ Symmetric Encryption (AES-CBC)

The AES implementation allows you to encrypt or decrypt blocks of data securely using a symmetric key shared between the sender and receiver.

- **Operational Mechanics:** Cipher Block Chaining (CBC) links each plaintext block with the previous ciphertext block via an XOR operation before encryption. This prevents identical blocks of plaintext from resulting in identical ciphertext.
- **Developer Considerations:** You must provide a unique, unpredictable Initialization Vector (IV) for every encryption operation to maintain confidentiality across multiple messages.
- **Deep Dive:** [AES Crypto Detailed API Guide](AESCrypto.mdx)

### 🔑 Digital Signatures (ECDSA)

Asymmetric cryptography allows secure verification without revealing private keys.

- **Supported Curves:** Full support for standard SECP elliptic curves, including `SECP192K1`, `SECP224K1`, and the industry-standard `SECP256K1` (commonly used in blockchain and secure network protocols).
- **Use Cases:** Used for authenticating firmware upgrades, establishing secure key exchange handshakes, or signing transactions from the wearable device.
- **Deep Dive:** [ECDSA Crypto Detailed API Guide](ECDSACrypto.mdx)

### 📑 Message Digests & HMAC Authentication

Message digests produce deterministic, fixed-size hashes from arbitrary binary inputs.

- **Streaming vs. One-shot:** The framework supports both one-shot calculations for small memory buffers and streaming architectures (Init/Update/Finalize) to process large files or incoming network streams without exhausting device RAM.
- **HMAC Layer:** HMAC implementations integrate a secret key into the hashing process, ensuring that the hash cannot be counterfeited by a man-in-the-middle attacker who lacks the key.
- **Deep Dive:** [Digest & HMAC Crypto Detailed API Guide](DigestCrypto.mdx)

### 📊 Checksums (CRC16 / CRC32)

Non-cryptographic operations focused entirely on execution speed and communication safety.

- **Functionality:** Designed to instantly catch random bit flips, hardware transmission drops, or flash memory corruption.
- **Performance Note:** Executes at near-native speeds with minimal battery impact, making it ideal for frequent internal loop checks. Do not use for authentication or security boundaries.
- **Deep Dive:** [CRC Checksum Detailed API Guide](CRCCrypto.mdx)

### 🔒 Hardware Key Encryption (PUF Module)

Zepp OS provides direct access to state-of-the-art silicon security via Physical Unclonable Functions (PUF).

- **Hardware-bound Security:** The `encryptKey` primitive wraps and encrypts sensitive application key material using unique cryptographic keys generated directly from microscopic, unreplicable variations in the device's silicon.
- **Zero Exposure:** Keys protected via this mechanism are completely locked to the physical wearable hardware and cannot be copied, cloned, or extracted via software exploits.
- **Deep Dive:** [Hardware Key Encryption (encryptKey) API Guide](encryptKey.mdx)
