# Message Digests & HMAC Hashing

The Hashing and Message Authentication Code (HMAC) architecture in Zepp OS provides crucial primitives for verifying data integrity and checking source authenticity.

### Message Digests (Hashing) vs. HMAC

1. **Message Digests (MD5, SHA-1, SHA-256):** These are one-way cryptographic hash functions that ingest variable-length data payloads and produce a unique, fixed-size mathematical fingerprint (checksum). They are deterministic: the exact same input always yields the exact same hash output. They are strictly used to verify that data has not been corrupted or altered randomly.
2. **HMAC (Hash-based Message Authentication Codes):** HMAC wraps a standard message digest function by blending it with a secret key (`private_key`). This guarantees **authenticity** alongside integrity. It ensures that an attacker cannot swap out data and compute a matching hash, because they lack the physical secret key required to generate a valid HMAC signature token.

### Execution Strategies: One-Shot vs. Streaming

- **One-Shot (`encrypt`):** Best for small data payloads already contained within device memory variables (e.g., short JSON blocks, individual attributes). It completes the initialization, processing, and finishing steps in a single operation.
- **Streaming (`start` / `update` / `finish`):** Indispensable for large file streaming, chunks downloaded over network sockets, or multi-packet application data buffers. It processes sequential text blocks incrementally, preventing out-of-memory errors on RAM-constrained wearable hardware.

## createCrypto

Constructs a standard Message Digest or an authenticated HMAC hashing pipeline context based on the supplied parameters.

### Algorithm Constants Reference

| algorithmId        | Category           |    Output Size     | Security & Environment Usage                                                                                          | API_LEVEL |
| :----------------- | :----------------- | :----------------: | :-------------------------------------------------------------------------------------------------------------------- | :-------: |
| `alg.MD5`          | Message Digest     | 16 Bytes (128-bit) | Cryptographically vulnerable to collision models. Use strictly for performance checks or legacy verification schemas. |   `3.0`   |
| `alg.HMACMD5`      | Authenticated HMAC | 16 Bytes (128-bit) | Integrates key authenticity over MD5. Avoid for new security designs; ideal for lightweight token checking.           |   `3.0`   |
| `alg.SHA_1`        | Message Digest     | 20 Bytes (160-bit) | Historically popular legacy standard. Prone to structural attacks; ideal only for backwards compatibility rules.      |   `3.0`   |
| `alg.HMAC_SHA_1`   | Authenticated HMAC | 20 Bytes (160-bit) | Authenticated wrapper using SHA-1. Used in classic signature handshakes.                                              |   `3.0`   |
| `alg.SHA_256`      | Message Digest     | 32 Bytes (256-bit) | Secure modern industry baseline standard. Fully recommended for high-security checksums and identity fingerprints.    |   `3.0`   |
| `alg.HMAC_SHA_256` | Authenticated HMAC | 32 Bytes (256-bit) | Highly secure signature layout. Perfect for mobile-to-watch network verification workflows.                           |   `3.0`   |

### Function Signatures

```ts
// Standard One-Way Hash Construction
function createCrypto(
  algorithmId: typeof alg.MD5 | typeof alg.SHA_256 | typeof alg.SHA_1,
  option?: DigestOptions
): DigestCrypto | undefined

// Authenticated Keyed HMAC Hashing Construction
function createCrypto(
  algorithmId: typeof alg.HMACMD5 | typeof alg.HMAC_SHA_256 | typeof alg.HMAC_SHA_1,
  option: HMACOptions
): DigestCrypto | undefined
```

## Configuration Parameter Scopes

### DigestData

Binary format container type designed to accept sequential buffers or arrays.

- **Type Constraints:** `number[]` | `ArrayBuffer` | `Uint8Array`

### DigestOptions

Configuration guidelines for standard unkeyed message digests.

| Property      | Type                  | Required | Default | Technical Description                                                                                              |
| :------------ | :-------------------- | :------: | :-----: | :----------------------------------------------------------------------------------------------------------------- |
| `key_encrypt` | `boolean` \| `number` |    No    |   `-`   | Flags if the operation should leverage inner PUF hardware configurations during low-level execution context loads. |

### HMACOptions

Required runtime structural options for building authenticated key-linked HMAC hashes.

| Property      | Type                  | Required | Default | Technical Description                                                                                    |
| :------------ | :-------------------- | :------: | :-----: | :------------------------------------------------------------------------------------------------------- |
| `private_key` | `DigestData`          | **Yes**  |   `-`   | The shared secret key payload utilized by the engine to lock the authenticity state of the text hash.    |
| `key_encrypt` | `boolean` \| `number` |    No    |   `-`   | Specifies if the secret key parameter has already been wrapped by the local device hardware PUF context. |

## DigestCrypto Instance Methods

### One-Shot Calculations

#### encrypt()

Executes immediate one-shot processing on an isolated input buffer block.

```ts
encrypt(data: createCrypto.DigestData): DigestResult | undefined
```

- **Returns:** A populated `DigestResult` mapping schema or `undefined` if computational validation fails.

---

### Streaming Operations (Incremental Chunk Ingestion)

#### start()

Initializes the internal calculation state, clearing buffer structures to accept new sequential data streams.

```ts
start(): void
```

#### update()

Appends a sequential raw binary data block segment into the running hash calculation matrix. Can be invoked multiple times sequentially.

```ts
update(data: createCrypto.DigestData): void
```

#### finish()

Concludes the incremental hashing loop, flushes internal pads, and produces the finalized signature block payload.

```ts
finish(): DigestResult | undefined
```

- **Returns:** A `DigestResult` containing the final immutable signature byte representation block or `undefined`.

---

### Structural Output Schemas

#### DigestResult

```ts
interface DigestResult {
  md_content: ArrayBuffer // The raw resulting binary digest signature array buffer
  length: number // Total byte length of the produced digest output
}
```

Calculate an MD5 digest in a single call. Suitable for small data (e.g., short strings or file checksums).

```js
import { alg, createCrypto } from '@zos/crypto'

const md5 = createCrypto(alg.MD5)

const result = md5.encrypt([65, 66, 67]) // Represents ASCII string "ABC"
```

Calculate a SHA-256 digest in a single call. SHA-256 produces a highly secure 32-byte hash fingerprint recommended for verifying application assets.

```js
import { alg, createCrypto } from '@zos/crypto'

const sha256 = createCrypto(alg.SHA_256)
```

```js
import { alg, createCrypto } from '@zos/crypto'

const hmac = createCrypto(alg.HMAC_SHA_256, { private_key: [1, 2, 3, 4, 5] })
```

Process large files or heavy incoming streaming segments safely using incremental step boundaries (`start`, `update`, `finish`).

```js
import { alg, createCrypto } from '@zos/crypto'

const digest = createCrypto(alg.SHA_256)
if (!digest) throw new Error('Failed to create digest instance')

// Begin the streaming pipeline context lifecycle
digest.start()
digest.update([65]) // Stream chunk 1: 'A'
digest.update([66, 67]) // Stream chunk 2: 'BC'
digest.update([68, 69, 70]) // Stream chunk 3: 'DEF'
const result = digest.finish()

if (result) {
  console.log(`Incremental streaming SHA-256 complete. Output size: ${result.length} bytes`)
}
```
